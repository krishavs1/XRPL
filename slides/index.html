One line: ERC-7730 for XRPL. A standard plus a reference library plus a working demo on a Ledger emulator.
The problem

You sign what you can't read

  • Every wallet builds its own transaction display.
  • Hardware wallets show raw fields, or ask you to turn on "Blind signing".
  • Batch: one signature, up to 8 hidden transactions.
Ledger's own XRP app has a "Blind signing" setting for types it can't render. That setting existing is our reason to exist.

Inspiration

Ethereum learned this the hard way

Feb 2025 · Bybit

$1.5B stolen through hardware-wallet signatures.

ERC-7730

Ethereum's fix: JSON metadata turns contract calls into readable intent.

XRPL

No equivalent, though its fixed transaction set makes it easier.

So we wrote one, and went further:
standard risk codes, Batch unfolding, scam-token detection.

EIP-712 (2017) only covered messages. ERC-7730 is Ledger's Clear Signing standard: metadata per contract, reviewed in a public registry, shown on the device screen. Risk codes, Batch recursion and impersonation detection are things ERC-7730 doesn't define.
The solution

One JSON file per transaction type


{
  "txType": "TrustSet",
  "title": "Set trustline",
  "intent": "Trust up to {LimitAmount.value}
    {LimitAmount.currency|currency} issued by
    {LimitAmount.issuer|account}.",
  "risks": [
    { "code": "CURRENCY_IMPERSONATION",
      "severity": "danger",
      "when": { "impersonates": {
        "currency": "LimitAmount.currency",
        "issuer":   "LimitAmount.issuer" } } }
  ]
}
  • A sentence in plain English
  • 23 standard risk codes, as data, not code
  • A registry that knows the real RLUSD issuer
  • 9 types today; a new type is one file
Abridged from packages/core/metadata/TrustSet.json. No expression strings, no eval: small enough for a hardware wallet. Deterministic: no AI or external service at signing time. Examples of codes: UNVERIFIED_ISSUER, UNLIMITED_TRUSTLINE, PARTIAL_PAYMENT, REGULAR_KEY_CHANGE, BATCH_MULTI_EXECUTION.

Next steps

Put the warnings on the Ledger itself

Why the XRP app can't do it yet

  • It can only list fields one by one. It has no way to show a plain-English summary or a warning screen.
  • It has no way to receive our metadata or issuer info, so it can't tell a real RLUSD from a fake.
  • A Ledger is small: it can't store a list of every token issuer.

How to fix it

  1. Teach Ledger's XRP app to show summaries and warnings. Its code is open source, and our fork is the starting point.
  2. Ledger approves it and ships it as a normal app update.
  3. Wallets send the Ledger a signed note saying who really issues each token, and the device checks it. Ethereum Ledgers already work this way.

Result: every wallet that uses a Ledger shows the warning, with no extra app.

The change goes into the XRP app that runs on the Ledger (LedgerHQ/app-xrp), not the device's operating system, so users just update the app. Today the app parses the transaction and shows each field as a raw label/value pair; its signing command takes only the transaction, so there's nowhere to pass metadata or registry entries. Only Ledger can ship the change, because devices only run Ledger-signed apps; our fork proves the warning works, on the emulator. Our patch targets app-xrp v2.8.1 on Stax and runs on Speculos, Ledger's emulator. Physical devices only accept apps Ledger has signed. The fork's verified-issuer list is hard-coded, which doesn't scale: hence the signed note. The note has to be signed because the device can't trust the computer it's plugged into. Our first version crashed doing heavy address encoding during review, which shows how tight device resources are.

Wallet ⇄ XRP Ledger, via QuickNode All live data runs through one QuickNode WebSocket endpoint: simulate, the live transaction feed, account history and submitting the signed transaction.
The wallet uses Ledger's Device Management Kit with the pre-release XRP signer kit (apps/demo/src/ledger.ts). Transport is WebHID for a real device over USB, or HTTP to Speculos for the emulator. The wallet serialises with xrpl's encode(), not encodeForSigning(): the XRP app adds the signing prefix itself. SigningPubKey is set to the device's public key before encoding. The DER signature goes into TxnSignature and the wallet submits to the XRP Ledger. The demo mirrors the emulator screen through Speculos's /screenshot and /events endpoints and forwards clicks to /finger. Speculos serves one client at a time. The third row is the proposal from the previous slide: it doesn't exist in the XRP app today. Network: every live call in the demo (simulate, the subscribe feed, balances, account_tx history, autofill, submit) goes through a single QuickNode WebSocket endpoint on XRPL testnet, set with VITE_XRPL_WSS in apps/demo/.env.local or the network button in the header (which shows the QuickNode host). WebSocket also avoids the public testnet JSON-RPC server's missing CORS headers. Static rendering with explain() needs no network at all.
